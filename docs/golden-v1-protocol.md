# Эталон v1: протокол сбора с юристами (F11)

Цель — 150–300 вопросов по темам с проверяемыми ожидаемыми нормами, чтобы карта точности
(`reports/accuracy.md`, `GET /accuracy`) отражала реальную практику, а не наши догадки.
Текущий файл `tests/golden/golden_v0.json` (version `v1-draft`, 75 вопросов, 14 тем) — стартовая точка.

## 1. Интервью (3–5 практиков, по 45 минут)

1. Какие 10 вопросов вам задают клиенты чаще всего? (по каждому: как формулирует клиент, какие нормы вы
   приводите в ответе, что в ответе самое рискованное).
2. На чём чаще всего ошибаются младшие юристы или чат-боты? (ловушки: отменённые нормы, письма
   Минфина, «народные» цифры, региональные особенности, переходные положения).
3. Вопросы с датой: что менялось за последние 3 года и где важно «на какую дату» (ставки, сроки, пени).
4. Вопросы-расчёты: пени, штрафы, сроки обжалования — с конкретными числами и ожидаемым результатом.
5. Вопросы, на которые правильный ответ — «этого нет в НК» или «нужен документ, которого нет».

Записываем дословно формулировку юриста: она попадает в поле `question`. Не «улучшаем» язык.

## 2. Формат вопроса

```json
{"id": "q101", "kind": "search | agent | agent_abstain", "topic": "НДС",
 "question": "формулировка практика", "query": "фраза для поиска (только для kind=search)",
 "expected": ["nk2.ch21.art164.p3"], "anchor": "фраза, обязанная быть в тексте ожидаемой единицы",
 "note": "почему такой ответ; для ловушек — в чём подвох"}
```

- `expected` — только ID единиц корпуса (`python -m taxcorpus search --hybrid "…"`, `unit --id …`),
  никогда по памяти. Тест `tests/test_golden_corpus.py` проверяет, что `anchor` дословно есть в
  тексте единицы, а `resolve`-вопросы резолвятся в ожидаемый ID.
- Для `kind=agent` можно несколько ожидаемых норм (например, срок + ст. 6.1 о порядке исчисления).
- `agent_abstain` — ожидается отказ или явное «нормы в корпусе нет»; `expected: []`.
- Темы (`topic`) — из списка `topics` файла; новую тему добавлять, если вопросов по ней ≥ 3.

## 3. Разметка и проверка

1. Черновик от юриста -> инженер находит ID через инструменты корпуса и вписывает `anchor`.
2. `python -m pytest tests/test_golden_corpus.py -q` — все якоря на месте.
3. Второй юрист подтверждает ожидаемые нормы (двойная разметка; расхождения — в `note`).
4. Целевая структура: не менее 10 вопросов на тему, 15–20 % ловушек, 20 % вопросов с датой.

## 4. Прогон и публикация

```bash
python scripts/eval_search.py                                # unit@5/article@5 по темам -> reports/eval_search.json
python scripts/eval_agent.py --repeat 3 --as-of 2026-09-10   # 3 повтора: разброс модели
python scripts/eval_agent.py --accuracy                      # reports/accuracy.{json,md}; GET /accuracy
python -m taxcorpus jobs run accuracy                        # то же по расписанию (jobs cron)
```

Публикуем метрики по темам и дате снимка корпуса; разброс по повторам показываем диапазоном.
Эталон открыт: любой может воспроизвести цифры.
